This SAIF file explaination is for the "accumulator.sv" design only. But consider it as a foundation explaination.

Now, the saif file generates the netwise activity of the design. For eg:-

    (extended_sum\[11\]   (T0 504000) (T1 510000)   (TX 0) (TC 201) (IG 0))
    (overflow             (T0 524000) (T1 490000)   (TX 0) (TC 98)  (IG 0))
    (acc_out\[3\]         (T0 489000) (T1 525000)   (TX 0) (TC 67)  (IG 0))
    (data_in\[1\]         (T0 514000) (T1 500000)   (TX 0) (TC 100) (IG 0))
    (enable               (T0 14000)  (T1 1000000)  (TX 0) (TC 2)   (IG 0))
    (rst_n                (T0 0)      (T1 1014000)  (TX 0) (TC 0)   (IG 0))
    (clk                  (T0 505000) (T1 509000)   (TX 0) (TC 203) (IG 0))

This is a model for certain nets that I have picked from the SAIF file. Here, there are few keyword mentioned:-

1. T0 - Total time(ps) the net was Logic 0
2. T1 - Total time(ps) the net was logic 1
3. TX - Total time(ps) the net was unknown 'X'
4. TC - Total nummber of logic transitions i.e. ( 1 -> 0 )  & (0 -> 1)
5. IG - Inertial glitch count reported by the simulator

Next there are 2 other terms for a net:-

Static probability -> How often the signal is High
Toggle -> How frequently it changes
* Two nets can have the same probability of being 1 but very different switching power

* "Extended_sum" is COMBINATIONAL, so it can change whenever "acc_out" or "data_in" changes.
    So, we will find more transitions in extended_sum i.e. TC = 201 can be lower as well for different values of transition in "acc__out" or "data_in".
    This transition tells the tool the frequency and hence it caluclate the power consumption in the design.

** THAT IS ONE OF THE REASON TO USE ENABLE IN THE DESIGN. BECAUSE IT STOPS THE TOGGLE OF BITS REGULARLY.
    AND THAT IS ALSO CAPTURED IN THE SAIF FILE. Hence, similar power estimation will be generated by Primetime tool.

* "acc_out" is SEQUENTIAL, so it can change only when "enable" is asserted. SO, it depends on enable so that it can change if required at an active edge.

## WE will see that "clk" has the highest "TC" value. because it is continuosly toggling in the design.
## Hence, consuming the most amount of power in the design.

Similarly , we can see about the "enable" and "reset" signal as well. That "enable" was high for 98.62% of time. and "reset" was initally 0 and 1 for the rest of the time hence (TC = 0).
